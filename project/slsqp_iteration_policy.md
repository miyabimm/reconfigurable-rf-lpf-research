# Phase 2 SLSQP反復上限の標準運用（現行 v2、v1履歴）

## 2026-10-20 改訂：停止理由に応じた標準手順（slsqp-staged-v2）

**今後の新規Phase 2・2段階SLSQP探索は v2 を標準**とする。RFの電気的な制約値、パレートの判定、過去EXPの終了状態は変更しない。新実装は `run_termination_aware_slsqp`、旧 `run_staged_slsqp` は再現性のため **v1として保存**する。

| 処理 | 粗格子SLSQP maxiter | 精密格子SLSQP maxiter | 追加実行条件 |
|---|---:|---:|---|
| **通常** | **240** | **120** | 新しい各初期値でまず実行 |
| **同一予算ウォーム再始動** | **240** | **120** | 粗格子が反復上限以外の理由（例：status4/8）で停止し、精密格子が正常収束した場合に限り、**精密格子の最終ベクトルから1回だけ** |
| **真の粗格子反復上限救済** | **500** | **280** | 粗格子が SLSQP status9 または明示的な Iteration limit で停止した場合、精密段階の最終ベクトルから粗・精密を各1回 |
| **真の精密格子反復上限救済** | — | **280** | **粗格子が正常収束しており**精密だけがstatus9の場合、精密を1回だけ |
| **粗格子status4/8＋精密格子非収束** | 延長しない | 延長しない | その初期値は失敗として保存し、別初期値・可行性改善・数値尺度調整を検討する |

- **一つの初期値につき最大4回のSLSQP段階呼出し**（通常2回＋許可された回復操作最大2回）。回復を繰り返さない。
- **個々のmaxiterの絶対上限は粗500／精密280**。通常設定240／120は変更しない。実験者判断で別の上限を試すときは、現行標準の上書きではなく、main事前予約の新EXP・バージョン化された逸脱記録として隔離する。
- 粗段階status4/8後に精密だけがstatus9となっても、**精密の回数を増やしただけでは粗段階の失敗は解消しない**ため自動増額しない。失敗の原因は「不等式制約が本当に数学的に不可能」とは限らず、局所的な可行解探索やSLSQP線探索に由来し得る。
- 粗・精密それぞれの `status`、`message`、`nit`、`nfev`、初期・最終ベクトル、ウォームスタート出典、回復tier、利用した上限をすべて保存する。**元の未収束フラグを遡及して書き換えない。**
- 収束状態と物理的適合性は独立。6設定の全帯域UL/DL・H2/H3密格子、連続帯域に関する未検証部分、SPD、独立MNA、電力収支は従来どおり独立に判定する。

### 実証根拠：EXP-060停止監査とEXP-061の対照再始動

- EXP-060の実行済み126試行中、62試行は両段階収束、64試行は未収束。主停止理由はstatus4が31、status8が29、status9が4。粗格子には240反復到達**0件**、最大229反復。精密格子の120反復到達4件は全件が既に粗格子status4であり、280反復救済でも両段階収束は0件。
- 粗格子がstatus4/8、精密格子がstatus0で終了した20件をEXP-061で対照検証。**同じ保存ベクトル**から通常240/120と増額500/280を別々に実行したところ、いずれも**20/20件が両段階収束、30dB適合、独立9×9 MNA PASS**。同一初期値の条件では、増額の有無による最終ILの実質的な差を観測しなかった。
- 結果はこの20件の局所最適化実験であり、他の64件すべてが再始動で収束する保証でも、一般的な「240/120が数学的に最適な計算量」という証明でもない。必要に応じて別の初期値・可行化手法を検討する。
- 証拠：EXP-060原Actions [39434590336](https://github.com/MasayaTakagi/reconfigurable-rf-lpf-research/actions/runs/39434590336)、停止監査 [39437882717](https://github.com/MasayaTakagi/reconfigurable-rf-lpf-research/actions/runs/39437882717)、EXP-061対照実行 [39439246405](https://github.com/MasayaTakagi/reconfigurable-rf-lpf-research/actions/runs/39439246405)。EXP-061は[PR #146](https://github.com/MasayaTakagi/reconfigurable-rf-lpf-research/pull/146)上で実行し、既往のEXP-060数値を書き換えない。

## 旧標準 v1（2026-10-20決定、数値上限はv2でも不変）


- **決定日:** 2026-10-20
- **承認の根拠:** ユーザー「適切な上限を設定して、今後の標準にしましょう」
- **適用:** 以後新たに作成するPhase 2のRF-LPF SLSQP 2段階最適化。RF-F003／RF-T005／RF-T006／RF-T007の**電気的制約自体は一切変更しない**。明示的に異なる最適化器・P4-A大量スクリーニング等を用いる場合は計算資源の上限をrun記録で区別する。
- **正本となる実装:** [`src/lpf/slsqp_budget.py`](../src/lpf/slsqp_budget.py)、回帰試験 [`tests/test_slsqp_budget.py`](../tests/test_slsqp_budget.py)。
- **位置づけ:** 数値探索の停止基準と計算資源の**運用規則**。RFの高調波・挿入損失・部品定数の仕様緩和ではない。Phase 2継続、Phase 3は別途ユーザー承認が必要。

## 標準の上限とリカバリ

| モード | 粗周波数格子でのSLSQP maxiter | 精密格子でのSLSQP maxiter | 用途 |
|---|---:|---:|---|
| **標準初回** | **240** | **120** | 通常の新トポロジーと保存解からの再最適化 |
| **上限到達時の救済（最大1回）** | **500** | **280** | SLSQPが明示的に `Iteration limit reached` 等で停止した場合のみ |
| **救済後も未収束** | 無限延長しない | 無限延長しない | `not_converged` を保存し、別初期値／別手法を検討 |

**240/120という通常値は採用した運用上の初期値であり、それ自体を比較実験で最良と証明したものではない。** 上限到達時のみ救済することで大量の簡易探索を安易に500/280に設定しない。成功した試行はmaxiterまで反復しない。**500/280も収束保証ではない**。

標準フロー：
1. 条件ID・制約ハッシュ・同じ回路接続・固定外部S2Pを照合した**保存済み検証解からウォームスタート**する。別条件の解を無検証で再利用しない。新構成は決定的な初期値を併用する。
2. 粗240／精密120上限で2段階最適化する。両段階の `success`、停止メッセージ、`nit`、関数評価回数、出力29等の完全ベクトルとseedを保存する。
3. 粗段階が反復上限で終了したら**その回の精密段階の出力を初期値として**粗500／精密280で**1回**再探索する。粗が正常収束して精密だけが反復上限に達した場合は、粗をやり直さず精密280のみ1回再探索する。
4. 非収束の原因が不適合／特異行列／線探索失敗／例外／Actionsジョブ時間切れであれば、**iteration limitとして扱わず**適切な別診断へ進む。ActionsのジョブタイムアウトとSLSQP反復上限を混同しない。
5. 初回・救済の**両結果を保持**し、数値的にH2/H3必須制約へ適合するかを元の帯域区間の密格子で再検査する。独立MNA、SPD、電力収支の合格を候補昇格の別条件とし、未収束の回のフラグを後で書き換えない。
6. runマニフェストと生結果に、`iteration_policy_id=slsqp-staged-v1`、通常240/120、救済500/280、ウォームスタートの元、`recovery_invoked`、各段階の終端理由・反復数・評価回数、実行時間、収束／未収束／失敗／未実行件数を残す。

**例（今後の新しい2段階専用ソルバー）**：

```python
from lpf.slsqp_budget import run_staged_slsqp, STANDARD_SLSQP_BUDGET

attempts = run_staged_slsqp(
    coarse_evaluator, fine_evaluator,
    saved_compatible_vector, attenuation_target_db,
    optimize_stage=optimize_stage,
    budget=STANDARD_SLSQP_BUDGET,
)
# attempts["attempts"] を両方保存すること。
# 各ベクトルは各周波数帯域の密格子でH2/H3 >= 必須値を検査し、
# 独立MNAと受動電力収支で確認してから候補に採用すること。
```

## 採用根拠と限界

- [EXP-055数値実行・Actions](https://github.com/MasayaTakagi/reconfigurable-rf-lpf-research/actions/runs/39341678211)：3DTC 4L探索18試行のうち13収束、5未収束。Cv1(2,4)／(0,1)の一部は粗160反復上限に到達。Actionsのジョブ自体は成功。最良4L面積5⅓はIL0.817365589761dBで収束済み。
- [EXP-056再探索・Actions](https://github.com/MasayaTakagi/reconfigurable-rf-lpf-research/actions/runs/39344219070)：未収束2構成の全6試行を**前回保存ベクトルからウォームスタート**し、粗500／精密280の上限で再探索。**6/6試行が両段階正常収束**、どの試行も粗98反復・精密27反復以内で終了。独立84点MNAとH2/H3≥30dB適合はPASS。新IL記録はなし（Cv1(2,4)=0.849084050391dB、Cv1(0,1)=0.857268582225dB）。
- 重要：**ウォームスタートと反復上限拡大は同時変更**なので、上限だけが原因と断定しない。通常240/120の妥当性も正式ベンチマークは未実施。今後のrunで収束率・計算時間・IL・反復分布を記録し、合理的な根拠が得られた場合だけ上限規則をバージョン付きで改定する。
- **過去のEXP-001～056のソルバー、実行済み数値、manifestおよび収束フラグを遡及更新しない。** 新ポリシー導入で古い実験が実行し直されたり、過去のソースのCLIデフォルトが切り替わったりしたことにはならない。
- GitHub Actionsの`timeout-minutes`（EXP-055/056では60分）はジョブ全体の壁時計制限であって、SLSQP maxiterの代替ではない。上限は初回／救済の合計で記録し、時間切れならcheckpointと未完了状態で保存。大規模探索はプロジェクト指示に従いWSL2を主な実行基盤とする。

正式RF-F003と試験RF-T007、観測済み局所パレート、物理モデルは不変更。Phase 3への移行は行わない。
